# 01 — Порядок определения применимости ТР ТС

> Выполнять для каждой позиции номенклатуры и для каждого регламента проекта отдельно. Регламенты в проекте — файл 07. Детали по каждому регламенту — чек-листы 02 (ТР ТС 032), 03 (ТР ТС 010), 04 (ТР ТС 012), 08 (ТР ТС 004), 09 (ТР ТС 020), 10 (ФНП 536). Решения пользователя — файл 05, они имеют приоритет.

## 2. Порядок по каждому регламенту

1. **Область применения** — относится ли изделие к видам продукции, на которые распространяется регламент (перечень вида изделий, идентификационные признаки).
2. **Исключения** — не попадает ли изделие или его применение в перечень продукции, на которую регламент не распространяется.
3. **Пороги** — превышены ли пороговые значения (давление, DN, P · DN, вместимость, температура).
4. **Категория** — где регламент её устанавливает (ТР ТС 032 — приложение 1).
5. **Форма подтверждения** — сертификат или декларация (и, если регламент это связывает, допустимые схемы).
6. **Вывод** — «Применим» / «Не применим» / «Не определено» + основание с пунктом и страницей PDF.

## 3. Вывод по позиции в целом

- Требуемые документы — по каждому применимому регламенту отдельно (например, арматура: сертификат или декларация по ТР ТС 032 **и** декларация по ТР ТС 010).
- Если хотя бы по одному регламенту «Не определено» — итог по позиции «Не определено» в этой части, с перечнем недостающих данных; по остальным регламентам вывод даётся.
- Электрическая часть: сначала ТР ТС 010 и 012; ТР ТС 004 не применяется к изделию, подлежащему 010 / 012 (кроме кабелей, проводов, шнуров); ТР ТС 020 проверяется независимо от них.
- ФНП 536 — не документ о подтверждении соответствия, а требования к применению на ОПО: в выводе указать, распространяются ли ФНП, категорию трубопровода пара и горячей воды (если применимо) и следствия (входной контроль п. 138, экспертиза промышленной безопасности п. 467).

## 4. Чего не делать

- Не определять применимость «по аналогии» с другой позицией без проверки параметров этой позиции.
- Не путать параметры проекта и параметры изделия: группа среды и исключения — по проекту (назначению); категория — по правилу файла 05.
- Не делать вывод по регламентам, которых нет в проекте (файл 07), и не цитировать их по памяти.
- Не оценивать действительность сертификатов и деклараций — это задача проектов проверки документов о качестве.
