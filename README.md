# ВК ТМЦ — проекты входного контроля

Репозиторий с материалами проектов входного контроля ТМЦ: инструкции, чек-листы, шаблоны выходных документов, тексты НД (Markdown) и их оригиналы (PDF).

**Навигация:**
- [`AGENTS.md`](AGENTS.md) — коротко для любого ИИ: с чего начать и обязательные правила;
- этот `README.md` — автовыбор проекта, сквозной порядок работы, имена выходных файлов, список проектов;
- [`INDEX_НД.md`](INDEX_НД.md) — где лежит любой ГОСТ / ОСТ / ТУ / ТР ТС / АТК (во всех проектах);
- [`GLOSSARY.md`](GLOSSARY.md) — словарь терминов и сокращений (ДК, Справка ПК, Справки РК, КРК, КИС …);
- `tools/check_repo.py` — самопроверка репозитория после правок.

## Как работать с репозиторием (для любого ИИ)

1. **Проект определяй сам** по разделу «Автовыбор проекта по заданию» ниже и сразу начинай работу — пользователь не обязан называть репозиторий и проект. Уточняй только позиции, которые не подходят ни под одно правило.
2. Прочитай `context.md` этого проекта — это инструкции проекта, работай строго по ним.
3. Прочитай `README.md` проекта — там список документов и известные потери при переносе в Markdown.
4. Работай с файлами папки выбранного проекта (при смешанном списке — каждой группы в своём проекте). НД из других проектов открывай, когда на них ссылается чек-лист или нужной нормы нет в своём проекте, — путь смотри в `INDEX_НД.md`.
5. Файлы, на которые инструкции ссылаются по имени (например, `05_Фланцы_ГОСТ_33259.md`), лежат в подпапках `docs/` этого проекта.
6. Если текст в `.md` вызывает сомнение (знаки `[знак]`, OCR, таблицы-картинки) — открой оригинал в `originals/` (имя совпадает, расширение `.pdf`) и цитируй по нему с пометкой «по оригиналу, стр. N».
7. **Списки файлов дочитывай до конца.** Инструменты чтения GitHub часто обрезают длинный список файлов папки (показывают первые ~30) и не показывают бинарные файлы (.docx, .xlsx, .pdf). Поэтому:
   - никогда не делай вывод «файла нет» или «папка `originals/` пустая» по обзору папки;
   - состав каждой папки `originals/` смотри в её `originals/README.md` — там полный список файлов с точными путями;
   - нужный файл открывай напрямую по полному пути (например, `fittings-flanges/originals/Шаблон_Справка_ПК.docx`), ветка `main`;
   - если файл из списка открыть всё же не удалось — так и скажи пользователю («файл есть в репозитории, но мой инструмент не читает .docx/.xlsx») и попроси загрузить его в чат, а не пиши, что его нет.
8. `spravki-rk`, `pipes`, `fittings-flanges` и др. — это **папки внутри репозитория [`otk2026/vk-tmc-projects-main`](https://github.com/otk2026/vk-tmc-projects-main)**, а не отдельные репозитории.

## Автовыбор проекта по заданию

Пользователь может прислать задание без названия проекта («проверь документы», перечень номенклатуры, паспорта, сертификаты, КРК, протоколы). Тогда проект определяется так — **сверху вниз, первое подходящее правило**:

**1. Проект назван прямо** («по проекту справки», «по КРК», «по фланцам») → он.

**2. Вид работы** (если это не проверка документов о качестве):

| Задание | Проект |
|---|---|
| Составить / разработать новую КРК, допуски, состав проверок | `krk-cards` |
| Внести результаты замеров в КРК по скану, фото, форме 1С | `krk-processing` |
| «Справки РК», справка для руководства: ДК, ВИК, ХА, УЗТ, УЗК, металлография, мехиспытания | `spravki-rk` |
| Требуется ли ТР ТС для номенклатуры, нужна ли сертификация или декларирование, применимость ТР ТС 032 / 010 / 012 / 004 / 020 или ФНП 536 по требованиям проекта | `tr-ts-applicability` |

**3. Проверка документов о качестве — по НД в обозначении позиции** (главный признак):

| НД в обозначении | Проект |
|---|---|
| ГОСТ 17375, 17376, 17378, 17379, 17380, 30753 (отводы, тройники, переходы, заглушки эллиптические); ГОСТ 33259, 12820, 12821, 12822 (фланцы); АТК 24.200.02-90 (заглушки фланцевые) | `fittings-flanges` |
| Любые ТУ на детали (ТУ 1469-016, 1469-006, 102-488 и др.); любые ОСТ 34 10.7xx-97 и другие ОСТ на детали | `details-tu-ost` |
| ГОСТ на трубы (8731, 8732, 8733, 10704, 10705, 10706, 3262, 20295, 9940, 9941, 9567 и др.) — труба как самостоятельная поставка | `pipes` |
| Трубы по ТУ (например, ТУ 14-3Р-1128-2007) | `details-tu-ost` |

**4. НД не указан — по виду изделия:**

| Изделие | Проект |
|---|---|
| Отвод, переход, тройник, заглушка, фланец, заглушка фланцевая | `fittings-flanges` |
| ОКШ, ОСС, ТШ, ТШС, ТШСР, ТС с давлением в МПа, ПШ, ПШС, ПШСК, ДШ, КП, муфты (обозначения по ТУ) | `details-tu-ost` |
| Труба | `pipes` |

**5. Смешанный список** (например, отводы по ГОСТ и тройники по ОСТ) — разбей позиции по проектам, каждую группу проверяй по `context.md` своего проекта, выходные документы (Акт, Справка ПК) — по правилам своего проекта. В начале ответа одной строкой укажи, какая позиция ушла в какой проект.

**6. Не подходит ни под одно правило** — проверь то, что определилось, а по остальным позициям задай один короткий вопрос.

Порядок после выбора — «Сквозной порядок работы» ниже.

## Сквозной порядок работы (любая задача — от начала до конца)

1. **Приём задания.** Определи, что прислано: перечень номенклатуры, паспорта, сертификаты, протоколы, КРК, сканы. Перечисли себе состав входных данных; если чего-то явно не хватает для задачи — продолжай с тем, что есть, и укажи недостающее в итоге (п. 7), а не останавливайся.
2. **Выбор проекта** — по разделу «Автовыбор проекта по заданию». Смешанный список — разбить по проектам.
3. **Чтение инструкций проекта:** `context.md` (главная инструкция) → `README.md` проекта → **все** файлы из раздела «Перед началом» `context.md` — полностью, от начала до конца (чек-лист вида продукции, решения и трактовки, правила оформления, шаблоны, применимые НД). Промежуточный отчёт о прочитанном пользователю не нужен.
4. **Выполнение** строго по порядку работы из `context.md` проекта и чек-листу. Нормы — только из НД репозитория (`INDEX_НД.md`); нет НД — «текст не приложен», без подстановки по памяти.
5. **Самопроверка.** Каждое несоответствие, опирающееся на число, знак, допуск или табличное значение, сверить со страницей PDF-оригинала. Готовые файлы открыть и сверить с требованиями правил оформления проекта и шаблона.
6. **Выходные файлы** — на основе шаблонов проекта (`originals/`), с именами по правилу «Имена выходных файлов».
7. **Итоговое сообщение:** какие файлы выданы; итог одной-двумя строками (принять / не принимать / запросить документы); какие поля оставлены пустыми (код КИС, № заявки, ФИО, даты) и что запросить у поставщика; одной строкой — какие файлы проекта и НД использованы (и какие не удалось открыть). Без пересказа содержимого файлов.

### Задача выполнена, когда

| Проект | Обязательно выдать |
|---|---|
| `fittings-flanges`, `pipes`, `details-tu-ost` | **Справка ПК** (.docx) — всегда; **Акт несоответствия ДК** (.xlsx) — при браковочных признаках или неопределённостях |
| `spravki-rk` | Отдельная **Справка РК** (.docx) на каждый запрошенный вид контроля |
| `krk-cards` | **КРК** (.xlsx) на каждую деталь — по правилам проекта |
| `krk-processing` | Заполненная **КРК** (.xlsx) — по правилам проекта |
| `tr-ts-applicability` | **Заключение о применимости ТР ТС** (.docx) |

…и итоговое сообщение по п. 7. Промежуточные списки требований и чек-листы пользователю не выдавать — он ждёт готовый результат.

## Имена выходных файлов

| Документ | Имя файла | Пример |
|---|---|---|
| Акт несоответствия ДК | `Акт_ДК_<поставщик>_<дата>.xlsx` | `Акт_ДК_Сантехкомплект_06.11.2026.xlsx` |
| Справка ПК | `Справка_ПК_<поставщик>_<дата>.docx` | `Справка_ПК_Сантехкомплект_06.11.2026.docx` |
| Справка РК | `Справка_РК_<вид>_<дата>.docx` | `Справка_РК_УЗТ_06.11.2026.docx` |
| Заключение о применимости ТР ТС | `Заключение_ТР_ТС_<объект>_<дата>.docx` | `Заключение_ТР_ТС_Котельная-Северная_08.11.2026.docx` |

- `<поставщик>` — краткое название без формы собственности и кавычек (ООО «Сантехкомплект» → `Сантехкомплект`); пробелы заменить на `-`.
- `<дата>` — дата оформления документа, `ДД.ММ.ГГГГ`.
- `<вид>` — `ДК`, `ВИК`, `ХА`, `УЗТ`, `УЗК`, `Металлография`, `Мехиспытания`.
- `<объект>` — краткое название объекта / проекта из требований (пробелы → `-`); нет названия — номер заявки или поставщик.
- Если в один день несколько документов с одинаковым именем (несколько поставок одного поставщика, несколько справок одного вида) — добавить в конец `_2`, `_3`.
- Имена КРК — по правилам проектов `krk-cards` и `krk-processing` (`КРК_<…>.xlsx`).

| [`krk-processing`](krk-processing/) | Обработка карт результатов контроля — **«обработка КРК»** | внести результаты замеров в КРК по скану, фото, форме 1С |
| [`spravki-rk`](spravki-rk/) | Справки по результатам контроля — **«справки РК»** | справки для руководства: ДК, ВИК, ХА, УЗТ, УЗК, металлография, механические испытания — только по прямому запросу |
| [`tr-ts-applicability`](tr-ts-applicability/) | ВК ТМЦ ➤ Применимость ТР ТС — **«применимость ТР ТС»** | требуется ли ТР ТС, сертификат или декларация, ТР ТС 032, 010, 012, 004, 020, ФНП 536, категория оборудования, ОПО, требования проекта, заключение о применимости |

**Трубы:** труба как самостоятельная поставка → `pipes`; сертификат на трубу или лист как полуфабрикат для детали или фланца → `fittings-flanges` (файл 06). Если из запроса непонятно — уточни.

**Справки:** «Справка ПК» (справка по несоответствиям поставщика) формируется автоматически вместе с Актом в проектах `fittings-flanges`, `pipes`, `details-tu-ost`. «Справки РК» (для руководства: ДК, ВИК, ХА, УЗТ, УЗК, металлография, мехиспытания) — только в `spravki-rk` и только когда пользователь прямо просит «справки РК». Сводная справка в проектах проверки не делается.

**ТР ТС:** «требуется ли ТР ТС на эту номенклатуру» → `tr-ts-applicability` (Заключение о применимости). Проверка приложенных сертификатов и деклараций ТР ТС в составе документов о качестве — по-прежнему в проектах проверки (`fittings-flanges`, `pipes`, `details-tu-ost`).

**КРК:** «составь КРК» → `krk-cards`; «внеси результаты / обработай КРК по скану» → `krk-processing`. Если пользователь назвал проект в запросе — работай по нему; если не назвал и задача подходит под несколько проектов — уточни.

## Структура каждого проекта

```
<папка-проекта>/
  README.md     — текущее состояние: список документов, замечания, известные потери текста
  CHANGELOG.md  — история изменений проекта (новые записи — в конец)
  context.md    — инструкции проекта (главный документ для работы)
  docs/         — Markdown-версии документов по темам
  originals/    — оригиналы (PDF, Word, Excel)
    README.md   — полный список файлов папки с точными путями
```

Корень репозитория: `README.md`, `AGENTS.md`, `CLAUDE.md`, `INDEX_НД.md`, `GLOSSARY.md`, `tools/` (`check_repo.py` — самопроверка, `check_repo_ignore.txt` — исключения).

**При добавлении проекта:** создать папку с такой же структурой, добавить строку в таблицу «Проекты» и правила в «Автовыбор проекта по заданию», запустить `python3 tools/check_repo.py --index`.

**После любых правок:** `python3 tools/check_repo.py` — должно быть «Замечаний нет».
