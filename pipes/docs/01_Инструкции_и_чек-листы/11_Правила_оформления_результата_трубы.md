# 11 — Правила оформления результата (трубы)
**Акт несоответствия ДК, Справка ПК (справка по несоответствиям)**

> Для проекта «ВК ТМЦ ➤ Трубы». Шаблоны — в базе проекта: Шаблон_Акт_несоответствия_ДК_xlsx.xlsx, Образец_Справка_детали_docx.docx (образец оформления Справки ПК). Формат образцов сохраняется, меняется только содержание.

## 1. Выходные документы

| Документ | Когда | Что в него идёт |
|---|---|---|
| **Акт несоответствия ДК** (xlsx) | При наличии браковочных признаков или неопределённостей. Один Акт — на одну позицию номенклатуры | Только браковочные признаки и требования представить недостающие документы |
| **Справка ПК** — справка по несоответствиям (docx) | Всегда, на каждую проверку (сертификат / поставку) | Всё: прослеживаемость, построчная проверка по всем критическим пунктам, замечания, допущения |

## 2. Акт несоответствия ДК (xlsx)
> Адреса ячеек и шрифты — раздел 8.2.
Заполняется строго по образцу с сохранением вёрстки, объединения ячеек, шрифтов, логотипа и настроек печати. Заполнять только значения полей. Заливку в Акт не вводить.

| Поле шаблона | Чем заполнять |
|---|---|
| Акт № / от | Номер — только если он дан. Если на тот же сертификат уже есть Акт — не назначать, запросить номер |
| Код КИС (НН) | Из задания; нет данных — пусто |
| Заявка на обеспечение | Из задания; нет данных — пусто |
| Наименование ТМЦ | Полное обозначение трубы (D × S, марка, группа, НД — ТУ и сортамент) |
| Количество (поставлено / НП) | По сертификату / заданию |
| Материал | Марка стали |
| № плавки | По сертификату; нет — «-» как в образце |
| НД на контроль | НД на трубы (ТУ / сортамент) |
| Документы, подтверждающие качество | Номер и дата сертификата (документа о качестве) |
| № изделия | Номер партии / труб по сертификату; нет — пусто |
| Поставщик | Наименование поставщика |
| Проекты применения | Из задания |
| Дата направления заявки на ВК | Из задания; нет данных — пусто |
| № п/п — Описание несоответствия | По формуле раздела 5 (суть — полужирный с подчёркиванием; «Требование:», «Факт:» — полужирные), каждое несоответствие — отдельной строкой |
| Подготовил сотрудник ОТК, Дата | Из задания; нет данных — пусто |
| Заключение | «Не годен» (вина поставщика) |

- Поля «Утвердил», «Комиссия Акта», ФИО и подписи — не менять.
- Поля, значений которых нет в исходных документах, оставлять пустыми и перечислять отдельно в сообщении. Значения не придумывать.
- Если несоответствий больше, чем строк в таблице шаблона, — не менять вёрстку самостоятельно, сообщить и спросить.

## 3. Справка ПК — справка по несоответствиям (docx)
> Точные числа оформления (ширины колонок, размеры шрифтов, выравнивание, отступы) — раздел 8.1.
«Справка ПК» (справка по поставщику) — рабочее название; заголовок в самом документе не меняется.
Формат: вертикальный А4 (книжная ориентация); поля, шрифт и ширина колонок — как в шаблоне Шаблон_Справка_ПК.docx. Шрифт Times New Roman.
**Шаблон оформления:** Шаблон_Справка_ПК.docx — для всех видов продукции. Из шаблона брать поля, шрифты, цвета, заливку графы «Оценка», ширины колонок и порядок разделов (0. Комплектность — 1. Прослеживаемость — 2. Сводная таблица по пунктам проверки — 3. Проверка происхождения данных — 4. Допущения — 5. Итог — 6. Документы к запросу). Шаблон — заполненная справка: всё её содержание (поставщик, документы, позиции, значения, выводы) полностью заменять данными текущей проверки, ничего из образца не оставлять. Текстовые образцы (Образец_Справка_детали_docx) — только примеры формулировок.

**Поля страницы (всегда, явно задавать в коде):** А4 книжная; левое 2,0 см, правое 1,0 см, верхнее 1,5 см, нижнее 1,5 см — как в проекте «Справки». Значения по умолчанию (2,54 см) и любые другие не использовать. Перед выдачей проверить поля в готовом файле.
**Заголовки (в справках всегда):** заголовок самой справки — тёмно-синий **1F4E79**, 14 пт, полужирный, ПРОПИСНЫМИ, по центру. Заголовки разделов («1. Прослеживаемость…», «2. Сводная таблица…» и т. д.) — тёмно-синий **1F4E79**, 12 пт, полужирный, по левому краю. Шрифт Times New Roman. Если в образце цвет заголовков другой — применять это правило.

**Структура:**
1. Заголовок «СПРАВКА ПО НЕСООТВЕТСТВИЯМ ДОКУМЕНТОВ ПО КАЧЕСТВУ».
2. Шапка: Поставщик; Изготовитель труб; Документы о качестве (номера, даты, вид 3.1/3.2, оригинал/копия); Объём проверки (НД на трубы с годом — ТУ и сортамент, группа / тип / класс прочности, марка стали, размеры, количество, партии); Акт несоответствия ДК (номер или пометка, что номер подлежит уточнению); Дата контроля.
3. **Раздел 1. Идентификация и прослеживаемость «сертификат — партия / плавка — позиция поставки»**: таблица Номенклатура | № и дата сертификата | Изготовитель | НД / группа | № партии / плавки | Количество (шт. / м / т) | Результат сверки с поставкой, заказом и КД; итоговая строка «Итого». Под таблицей — вывод текстом.
4. **Раздел 2. Сводная таблица по пунктам проверки**: по каждой позиции — общие пункты файла 01 и критические пункты чек-листа НД на трубу.
   Колонки: (№) | Номенклатура | Пункт проверки | Ссылка на НД | Описание несоответствия | Оценка. Ячейки «Номенклатура» объединяются по вертикали.
5. Раздел «Проверка происхождения данных» и раздел допущений (группа, редакция НД, требования заказа, если заказ не приложен) — если применялись.
6. Итог: что является браком металла / трубы, а что — документальным несоответствием, устранимым допредъявлением документов.
7. Перечень документов к запросу у поставщика (оригиналы / заверенные копии сертификатов, протоколы, заказ, документы ТР ТС).
8. «Справку составил: инженер ОТК ____ / ____ /», «Дата».

## 4. Комплект выходных документов
По каждой проверке формируются только два документа: **Справка ПК** (всегда) и **Акт несоответствия ДК** (при браковочных признаках или неопределённостях). **Сводная справка в этом проекте не формируется** (решение от 01.11.2026, заменяет решение от 28.09.2026). Справки для руководства (**Справки РК**: ДК, ВИК, ХА, УЗТ) оформляются в отдельном проекте «Справки по результатам контроля» только по прямому запросу.

## 5. Формула описания несоответствия
Каждое несоответствие — три части, каждая с новой строки внутри ячейки «Описание несоответствия» (в Акте и в справке):
1. **Краткое описание** — одно предложение о сути отклонения, без подробностей и обоснований.
2. **«Требование:»** — конкретный пункт, таблица или примечание с нормируемым значением.
3. **«Факт:»** — позиция, документ и конкретное значение (или что графа не заполнена / документ не представлен).

### Оформление ячейки «Описание несоответствия» в Акте (xlsx) — строго как в образце Акта
Одна ячейка — одно несоответствие, три абзаца (перенос строки внутри ячейки, Alt+Enter / `\n`). Шрифт Arial 10, чёрный.

| Часть | Начертание |
|---|---|
| 1-я строка — суть несоответствия (одно предложение с точкой) | **полужирный + подчёркнутый** — вся строка |
| «Требование:» | **полужирный** только слово «Требование:»; далее обычным шрифтом |
| «Факт:» | **полужирный** только слово «Факт:»; далее обычным шрифтом |

Образец из Акта:
> <b><u>Не представлены сведения о полуфабрикате и документ о качестве завода-изготовителя полуфабриката.</u></b>
> <b>Требование:</b> п. 5.3 и приложение А ГОСТ 17380-2001 (раздел «Сведения о полуфабрикате»), пп. 5.2.3, 5.2.4 ГОСТ 17380-2001.
> <b>Факт:</b> в паспорте № 0000-003218/1 раздел «Сведения о полуфабрикате» отсутствует; номер плавки, партии заготовки и изготовитель трубы-полуфабриката не указаны; сертификат на полуфабрикат на партию 629 не представлен.

**Перенос строк — обязателен.** «Требование:» и «Факт:» всегда начинаются с новой строки. Типовая ошибка: «…не соответствует КД.Требование:» — так оформлять нельзя.
⚠️ Перенос `\n` **нельзя** записывать отдельным фрагментом, состоящим только из пробелов / переноса: openpyxl сохраняет такой фрагмент без `xml:space="preserve"`, и Excel его удаляет — строки склеиваются. Перенос ставится **в начало** полужирного фрагмента: `"\nТребование:"`, `"\nФакт:"`.

Техника (при формировании xlsx кодом) — делать ровно так:
```python
from openpyxl.cell.rich_text import CellRichText, TextBlock
from openpyxl.cell.text import InlineFont
from openpyxl.styles import Alignment
F = dict(rFont="Arial", sz=10)
cell.value = CellRichText(
    TextBlock(InlineFont(**F, b=True, u="single"), sut),      # суть, с точкой в конце, без переноса
    TextBlock(InlineFont(**F, b=True), "\nТребование:"),      # перенос — внутри этого фрагмента
    TextBlock(InlineFont(**F), " " + treb),
    TextBlock(InlineFont(**F, b=True), "\nФакт:"),            # перенос — внутри этого фрагмента
    TextBlock(InlineFont(**F), " " + fakt),
)
cell.alignment = Alignment(wrap_text=True, vertical="top", horizontal="left")
```
**Проверка перед выдачей Акта (обязательно, по сохранённому файлу):**
```python
import zipfile, re
x = zipfile.ZipFile(path).read("xl/worksheets/sheet1.xml").decode("utf-8")
assert not re.search(r"<t>\s+</t>", x), "есть фрагмент из одних пробелов — Excel склеит строки"
assert not re.search(r"<t>\n", x), "перенос в <t> без xml:space=preserve"
```
Также для каждой ячейки описания `str(cell.value)` содержит ровно два `\n`, строка 2 начинается с «Требование:», строка 3 — с «Факт:». Если проверка не прошла — исправить и проверить снова. Высоту строки не уменьшать: текст должен быть виден целиком.
В Справке (docx) — та же структура в ячейке «Описание несоответствия»: 1-я строка полужирная с подчёркиванием, «Требование:» и «Факт:» — полужирные, остальное обычным шрифтом.

### Стиль формулировок в Акте — профессионально, без воды
- **Суть** — одно короткое предложение, начинается с сути: «Не подтверждена…», «Не представлен…», «Превышено содержание…», «Не соответствует…». Без «В ходе проверки установлено, что…», «Следует отметить…», «Как видно из…».
- **Требование:** — только ссылка на НД (пункт, таблица, примечание, редакция) и через тире нормируемое значение или суть требования. Без пересказа стандарта и пояснений, зачем требование нужно.
- **Факт:** — документ (номер, позиция, партия / плавка) и фактическое значение или «графа не заполнена», «не представлен», «не указан». Без выводов, оценок и предположений.
- Одно несоответствие — одна ячейка. Не объединять разные несоответствия в одну строку.
- Трактовки, допущения, варианты, «признаки подстановки данных», рассуждения — только в Справку, не в Акт.
- Слова «возможно», «вероятно», «по-видимому», «формально», «рекомендуется» в Акте не использовать.
- Для неопределённости суть формулируется как требование к документу: «Не представлен протокол…», «Не подтверждено…», а не «Несоответствие…».

Плохо → хорошо:
> ✗ «В ходе проверки установлено, что в представленном паспорте отсутствуют сведения о значении относительного сужения, что не позволяет оценить соответствие металла требованиям нормативной документации.»
> ✓ <b><u>Не определено относительное сужение ψ.</u></b> / <b>Требование:</b> п. 6.6.3 ГОСТ 17380-2001 — ψ определяют для деталей, подконтрольных органам надзора (индекс «П»). / <b>Факт:</b> паспорт № ___, поз. 1 (Отвод П90-57×5-09Г2С) — графа ψ: прочерк.

Пример:
> Не подтверждена ударная вязкость основного металла (результаты отсутствуют).
> Требование: п. 2.12, табл. 4 ГОСТ 10705-80 — KCU для термообработанных по всему объёму труб группы В толщиной стенки 6 мм и более.
> Факт: сертификат № ___ от ___, партия ___ (труба 219×8, сталь 20, гр. В) — графа не заполнена, протокол не представлен.

Пример:
> Марка стали не предусмотрена стандартом на трубы.
> Требование: п. 1.2 ГОСТ 10706-76 — трубы групп А, Б, В изготовляют из стали марок Ст2, Ст3 и низколегированной стали.
> Факт: сертификат № ___, поз. 2 — труба 530×8 ГОСТ 10706-76, группа В, сталь 20.

Если несоответствия нет, в справке: «Несоответствий не выявлено.» + «Требование: …» + «Факт: …».
Формулировки краткие, без вводных оборотов, пересказа норм и оценочных суждений. Всё, что не укладывается в три части, — в текст справки.

## 6. Цветовое кодирование (только в справках)
Заливкой выделяется только ячейка графы «Оценка». Остальные графы не заливаются.

| Цвет (HEX) | Когда | Формулировки графы «Оценка» |
|---|---|---|
| 92D050 зелёный | Требование выполнено полностью, без оговорок | «Соответствует» |
| FFFF00 жёлтый | Замечание, не браковочный признак: частичное выполнение, редакционный дефект, показатель не нормируется / не требуется / не проверялся, соответствие с оговоркой | «Соответствует (неполнота по …)»; «Частично (…)»; «Подлежит исправлению (не браковочный признак)»; «Не применимо (…)»; «Не требуется (…)»; «Не нормируется (…)»; «Не проверялось (…)» |
| FF0000 красный | Браковочный признак или неопределённость | «НЕ СООТВЕТСТВУЕТ»; «Не подтверждено (…)» |
| E8E8E8 светло-серый | Шапка таблицы; текст шапки полужирный | — |
| F2F2F2 серый | Итоговая строка «Итого» (кроме графы «Оценка» — она по общему правилу) | — |

- Цвет текста в окрашенных ячейках не менять: чёрный (авто), обычное начертание. Полужирная — только шапка; исключение — ячейка «Описание несоответствия»: суть (полужирный с подчёркиванием), «Требование:» и «Факт:» (полужирные), см. раздел 5.
- В OOXML заливка: `<w:shd w:val="clear" w:color="auto" w:fill="КОД"/>` в свойствах ячейки. Тип «сплошная» (SOLID) не применять — отображается чёрным.
- «НЕ СООТВЕТСТВУЕТ» и «Не подтверждено» — оба красные; различие передаётся текстом.
- Оценка с уточнением в скобках, снижающим её (неполнота, частично, сверка не выполнена, значение справочное), — жёлтая, не зелёная.
- Браковочные признаки жёлтым не помечать — справка не должна расходиться с Актом.

## 7. Правила формулировок
1. Три категории выводов не смешивать: браковочный признак → Акт; замечание → только справка; неопределённость → Акт как требование представить документ, без вывода по существу. Замечание, поданное как браковочный признак, обесценивает претензию целиком.
2. «Не соответствует» (прямое отклонение) и «не подтверждено» (нет подтверждения) — разные основания для претензии.
3. Разделять документальные несоответствия (устранимы допредъявлением документов) и брак металла или конструкции. Если брака нет — сказать прямо.
4. Не выдавать допустимое по стандарту за нарушение — см. раздел «Что НЕ является нарушением» в чек-листе и файл 09.
5. Допущения излагать открытым текстом с источником, в отдельном разделе справки.
6. Не додумывать данные. «Проверка невозможна, требуется документ ___» — самостоятельный результат.
7. Ссылка всегда на конкретный пункт / таблицу / примечание / сноску, проверяемые по приложенным текстам. Ссылку на НД ставить только там, где есть прямая норма.
8. Если норма в задании расходится с действующей редакцией стандарта — применять стандарт и отдельно указать на необходимость актуализации карты входного контроля.

## 8. Точные параметры оформления (сняты с шаблонов 08.11.2026)

> Лучший способ — **открыть копию шаблона и заменить в ней содержимое** (тогда всё ниже сохраняется само). Если инструмент не умеет редактировать шаблон и строит файл заново — задавать **все** параметры ниже явно; значения по умолчанию своего инструмента не использовать. Перед выдачей сверить готовый файл с этим разделом.

### 8.1. Справка ПК (`Шаблон_Справка_ПК.docx`)

**Страница и текст**

| Параметр | Значение |
|---|---|
